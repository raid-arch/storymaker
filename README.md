# 綴庭 — 創作世界観ノート

長編作品の人物・世界観・家系・歴史・伏線を関連付けて管理する、日本語の個人用Webアプリです。React + TypeScript + Vite + Tailwind CSS で実装しています。基本機能はログイン・バックエンド・有料API・外部フォントなしで使えます。任意の自動同期には、データ専用の非公開GitHubリポジトリと接続キーを使用します。

## 開発

Node.js 22.12 以上（この環境では 24.19）と npm を使用します。

```bash
cd /workspace/storymaker
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173 --strictPort
```

他のマシンではキャッシュ指定を省略できます。開発サーバーのポートが使用中の場合は、別のポートを明示してください。チェックアウトはタスクごとに隔離されているため、新しい Git worktree は不要です。

```bash
npm run typecheck
npm test
npm run build
npm run preview -- --port 4173 --strictPort
```

PWA とオフラインキャッシュは本番ビルドで有効です。`dev` ではサービスワーカーを登録しません。本番公開は `dist/` をHTTPS対応の静的ホスティングへ配置します。外部サービスの契約は必須ではありません。このリポジトリではデプロイは実行していません。

## 操作

1. 初回は作品・人物・事件・伏線がない空の状態です。サンプルは自動登録せず、サンプルの追加ボタンもありません。保存済みの作品は初期化せず、そのまま読み込みます。
2. サイドバーの作品名から切替・新規作成・管理を行えます。「種類」と「上位プロジェクト」でシリーズ → 作品 → 章を構成します。管理一覧には上位のパスを表示します。
3. 新しい設定は名前を決めて作成します。作成後の詳細編集は自動保存です。新規作成前の未確定フォームは、キャンセルすると破棄されます。
4. 人物には別名、性別、年齢、誕生日、生存状況、外見、性格、能力、経歴、所属、自由項目を記録できます。画像は1枚3MB以下です。設定には確定状態・タグ・作中の通説・実際の真相を別々に保存できます。
5. 詳細の「関連する設定」で、同じ作品や別作品の設定をリンクできます。リンク先にはリンク元が表示されます。国家・組織・一族の名前を入力した後、該当する世界観設定をリンクすると相互参照できます。
6. 家系図は同じプロジェクトの人物を表示します。「関係をつなぐ」で親子・兄弟姉妹・婚姻・養子・友人・敵対などを登録します。親子・養子の循環は登録できません。人物の「系統」で本家／分家を、「世代」で世代を指定できます。未指定の世代は親子関係から算出します。「配置を編集」でドラッグ移動し、通常モードの人物選択で詳細へ移動します。拡大縮小とスクロールに対応しています。
7. 年表の「年代」は共通暦の数値です。紀元前は負数、年代未確定は空欄にします。「時期」に暦名や季節・月日などを補足できます。事件を人物・国家・一族へリンクすると、一つの事件がそれぞれの年表にも表示されます。
8. 伏線には初登場・関連人物や事件・真相・回収予定・回収状態を記録します。初登場の欄ではプロジェクト名を候補として表示します。
9. 上部の検索は全作品の名前・本文・真相・自由項目・タグを対象にします。空白で複数語を指定でき、`#タグ` も検索できます。⌘K／Ctrl+Kで検索欄を選択します。
10. ごみ箱の操作は確認してから削除します。上部の取り消しボタンで直近30操作を戻せます。連続入力はひとまとまりになります。取り消し履歴はメモリ上だけに保持され、再読み込みで消えます。

## 保存・バックアップ・端末間移行

データは各ブラウザ・オリジンの IndexedDB に保存されます。自動保存の「保存済み」を確認してから画面を閉じてください。保存失敗時には通知と再試行・JSON書き出しを表示します。読み込み失敗時はサンプルで上書きしません。

「設定・バックアップ」で全プロジェクト・画像・リンク・人物関係をJSONとして書き出せます。復元は形式と参照整合性を検証してから確認画面を表示し、現在の全データを置き換えます。実行前に現在のJSONを書き出せます。復元直後は取り消しも可能です。Markdown書き出しは選択作品と下位プロジェクトのテキスト・リンク・人物関係を含み、画像を含みません。Markdownは復元用ではありません。

端末間では、設定画面から任意の非公開GitHub同期を接続できます。接続しない場合も、PCからJSONを書き出し、Androidへファイルを移して復元することで移行できます。プライベートブラウズの終了、ブラウザデータ削除、端末故障ではローカルデータを失う可能性があります。JSONを端末外にも保管してください。同じデータを複数タブで同時編集せず、一つのタブで編集してください。

画面上部の「アプリをインストール」ボタンで、対応ブラウザのインストール画面を開けます。画面を開けない場合はブラウザ別の追加手順を表示します。ブラウザ側の既存インストール情報を強制的に解除する機能ではありません。

Android Chromeのメニューから「ホーム画面に追加」または「アプリをインストール」、PCの対応ブラウザではインストール操作を利用できます。最初のオンライン読み込みでアプリのキャッシュが完了した後はオフラインで起動・編集できます。更新時には画面上部に通知が表示され、保存後に更新できます。ブラウザごとのインストールUIや永続保存の許可はブラウザ側の判断によります。

## 検証

```bash
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2Eテストは本番ビルドと `/usr/bin/chromium` を使用します。他の環境では `CHROMIUM_PATH` を指定してください。ポート4173をテスト専用に空けておきます。デスクトップとPixel 7相当のChromiumエミュレーションで、作成・編集・再読み込み・関連リンク・削除確認・取り消し・家系関係・年代順・バックアップ復元・Markdown・オフライン再読み込みと編集を検証します。Android実機そのものの検証ではありません。

`src/model.test.ts` はバックアップの不正形式・参照整合性、階層削除、検索、年代順、Markdownを検証します。`src/storage.test.ts` は IndexedDB の初期化とユーザー変更の保持を検証します。

## 実装の構成

- `src/model.ts`: データ型、空の初期状態、検索、削除整合性、バックアップ検証、Markdown
- `src/storage.ts`: IndexedDBへの読み書き。初期データは保存レコードがないときだけ作成
- `src/App.tsx`: プロジェクト・画面遷移・逐次自動保存・操作履歴・年表・伏線・バックアップ
- `src/Editors.tsx`: プロジェクト／設定編集、画像、タグ、自由項目、リンク元
- `src/Graph.tsx`: 家系図・関係登録・世代配置・ドラッグ
- `src/style.css`: ダーク／ライトテーマ、PCとスマートフォンのレイアウト

初期版では長文はプレーンテキストで編集します。非公開GitHubとの同期は、主に一方の端末ずつ使用する場合を対象にしています。共同編集・変更内容の自動統合・リッチテキスト・独自暦の変換は実装範囲に含めていません。数十世代の家系を表現できますが、数万件のデータに対する仮想スクロールや全文索引は未実装です。

## GitHub Pagesへの公開

`.github/workflows/pages.yml` により、mainへのpush時に型チェック・テスト・ビルド後にGitHub Pagesへデプロイします。GitHubのリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。初回の設定後はActionsの **Publish GitHub Pages → Run workflow** を実行するか、失敗した実行を再実行します。

公開先は `https://raid-arch.github.io/storymaker/` です。有効化とデプロイの成功後に利用できます。ビルドでは `VITE_BASE_PATH=/storymaker/` を指定し、画像・アプリ・サービスワーカー・ホーム画面からの起動先をそのパスに揃えます。ローカル開発では未指定の `/` を使用します。

```bash
VITE_BASE_PATH=/storymaker/ npm run build
VITE_BASE_PATH=/storymaker/ npm run preview -- --port 4173 --strictPort
# Pages配下のURL・オフライン動作も検証
VITE_BASE_PATH=/storymaker/ npm run test:e2e
```

公開アプリの配信ファイルには、利用者の作品や初期サンプルを含めません。ブラウザ内で作成した作品データはアップロードされません。公開URLのIndexedDBは開発環境とは別なので、必要なデータはJSONで移行してください。

## 見た目のカスタマイズ

ホーム画面の「カスタマイズ」または「設定・バックアップ」から、テーマの明暗・セージ／ブルー／ラベンダー／アンバー・文字サイズ・本文の書体・余白・カード／リスト表示を変更できます。ホーム画面の紹介・件数・最近の設定・伏線・バックアップ案内は非表示や並べ替えができます。文字サイズはナビゲーションやフォームにも反映します。変更はすぐ反映され、IndexedDBとJSONバックアップに保存します。過去のバックアップに表示設定がなくても読み込めます。「表示設定を初期状態に戻す」は作品データを削除しません。

## 非公開GitHubへの自動同期（任意）

公開アプリ用の `raid-arch/storymaker` とは別に、データ専用の **Private** リポジトリ（推奨名 `storymaker-data`）をGitHubで作成します。アプリの接続画面に作成リンクがあります。こちらの開発環境のGitHub連携では新規リポジトリ作成権限がないため、ユーザーによる作成が必要です。

1. GitHubの **Settings → Developer settings → Personal access tokens → Fine-grained tokens** でキーを作成します。**Repository access → Only select repositories** でデータ専用リポジトリだけを選び、**Repository permissions → Contents → Read and write** に設定します。期限を設定してください。
2. 両端末で綴庭の **設定・バックアップ → PC・スマホの自動同期** に所有者名・非公開リポジトリ名・接続キーを入力します。キーをチャットへ送ったり、公開リポジトリに保存しないでください。
3. 最初の端末では「この端末の内容を初めてクラウドに保存」を選びます。既存ファイルがある場合は、どちらの全データを使うか明示的に選びます。
4. もう一方の端末では「クラウドの最新版をこの端末で使う」を選びます。サンプルでクラウドを自動上書きしません。
5. 以後はローカル保存完了後の約1.8秒、アプリに戻ったとき、オンライン復帰時、オンラインかつ画面表示中の約1分おきに同期を確認します。手動の「今すぐ同期」も使えます。端末を切り替える前に「同期済み」を確認してください。

保存先は `tsuzuriniwa/data.json` です。無料のGitHub APIを使用し、有料API・Driveの容量・独自サーバーは使いません。リポジトリがPublicの場合は接続を拒否し、その後の同期でもPrivateであることを再確認します。接続キーはアプリからGitHub APIへだけ送信します。「この端末に接続情報を保存する」を選ぶと、IndexedDBの作品とは別のキーに接続情報を保持します。選ばない場合はページ再読み込み／アプリ終了までメモリ上に保持します。どちらの場合も作品JSON・Markdown・GitHubの同期ファイルに接続キーを含めません。接続解除で保存したキーを削除します。PCとスマホでそれぞれ設定が必要です。

同期の基準となるファイルSHAとデータのハッシュを保持します。両方の端末が変更された、またはクラウドのファイルが削除された場合は自動同期を止め、どちらの全データを使うか確認します。設定を細かく統合する機能ではありません。GitHubへの書き込みにも期待するSHAを渡し、確認後の別端末の書き込みを409エラーで検出します。確認中にクラウドが変わった場合は再選択を求めます。

読み込み前の端末データ、または手動で置き換える前のクラウドデータは、端末内の「同期前の保護コピー」に保存します（最新の1件）。設定画面からJSONとして書き出せます。保護コピーを保存できない場合や編集中に内容が変わった場合は、端末への読み込みを止めます。GitHub側にもファイルの変更履歴が残ります。

画像を含む1スナップショットの上限は **10MB** です。GitHubのファイル履歴は更新ごとに増えるので、画像を大量・頻繁に変更する用途には向きません。キーの期限切れ・権限不足・通信失敗・API利用制限時は同期エラーを表示します。ローカル保存とJSONバックアップは継続して利用できます。無料枠やサービスの条件はGitHub側の規定に従います。

同期の自動テストではGitHub APIを模擬し、初回の選択、別ブラウザへの読み込み、競合停止、公開リポジトリ拒否、キーを含まないバックアップを確認しています。ユーザーの実際の非公開リポジトリとの接続は、リポジトリ作成とキー入力後に確認が必要です。

## 初期状態とプライバシー

新しいブラウザ・端末では空の状態から始まります。以前から同じブラウザにある作品は消しません。データを持つ端末からは、JSON復元や明示的に接続した非公開同期を使って引き継げます。第三者の端末へ作品を自動配信する機能はありません。表示設定のプレビューも固有の作品名を使いません。テストのデータは `tests/sample.ts` の合成データで、アプリからは参照しません。

この変更は端末のロックやログイン認証ではありません。同じブラウザ・端末を他の人に渡すと、そのブラウザに保存済みの作品は開けます。公開リポジトリの過去のコミット履歴や、既に閲覧・保存された旧版の配信ファイルはこの変更では消去しません。

## 自由記述と候補

作品の種類・設定の状態・人物の生存状況・系統・世界観カテゴリ・伏線の回収状況・人物の関係名は自由に入力できます。「候補」は任意で、使わずに好きな名称を記入しても自動保存されます。既に記録した値は、ほかの設定を編集する際の候補にも表示します。独自の状態・カテゴリ・回収状況・系統は一覧や家系図の絞り込みにも表示します。カテゴリは一覧の「＋カテゴリ」、独自の設定項目は詳細画面の「＋項目を追加」からも増やせます。

人物リンクや上位プロジェクトは参照先のIDを保つため既存データを指定します。世代と共通暦の年代は配置・並べ替えに使う数値です。関係名の「親子」「養子」は世代配置と循環チェックに、「回収済み」はホーム画面の未回収件数の集計に使います。それ以外の名称も保存できますが、これらの意味を自動推測することはしません。独自の名称を含むJSON・同期データは、両端末でアプリを更新してから利用してください。
