# ストーリー制作画面のリワーク（1.1.0）

ストーリーを開くと「プロット設計」から制作を始める。世界観は独立した参照資料として維持し、ストーリーの展開・場面の状態・伏線の配置は作品ごとに作る。前回開いていた作業・設計図の表示方法・シーンを端末内で記憶する。

## 制作の流れ

1. 「この物語を一文で」に全体の軸を記入する。必要に応じて折りたたみを開き、テーマ・出発点・全体のあらすじ・結末・目標文字数を設計する。
2. 自由な章を追加する。三幕構成／起承転結／序破急のひな形も明示的に選べる。ひな形は空の章を追加するだけで本文や設定を上書きしない。
3. 章ごとにシーンカードを作る。目的・対立・結果・視点人物・緊張度・進行状態を自動保存する。カード上であらすじと本文文字数を把握できる。
4. PCではドラッグ、スマホでは前後ボタンと移動先の章選択で並べ替える。章自体の前後移動も可能。
5. 「あらすじ通読」で全体の流れ、「本文を通読」で章順の原稿を読む。未分類は最後に置き、本文の書き出し順も揃える。
6. 「人物の登場表」で人物×シーンの交点を切り替える。「伏線の配置」で提示／示唆／回収を割り当てる。伏線の作成も作品内で行える。
7. カードから「本文を書く」へ移り、場面の目的・対立・変化・視点を参照しながら執筆する。世界の事件・場所・時点・その場の人物状態も従来どおり編集できる。「設計図へ戻る」で構成へ戻る。

## 保存と互換性

- Project.storyPlan は省略可能な文字列辞書。テーマ等を別作品や共通世界観に波及させない。
- Scene に省略可能な purpose / conflict / outcome / povId / tension（0〜5整数）/ clueBeats（伏線ID→配置）を追加。既存シーンの本文・メモ・時間・人物の状態は保持する。
- 人物削除時は視点の参照を解除し、伏線削除時は配置を解除する。伏線を配置しても元の共有設定の「回収済み」状態や真相は変更しない。
- 部分ファイルの書き出し・追加取り込みで、新しい視点IDと伏線配置のキーも正しく振り直す。storyPlan の文章はID置換の対象にしない。
- IndexedDB・JSONの基本バージョンは変更せず、旧データは新しい項目なしで読み込める。新規利用時に作品やサンプルは登録しない。

確認：型チェック、単体テスト、PC・Pixel 7相当の操作確認。設計→シーン移動→登場表→伏線配置→執筆→再読み込み、ドラッグとボタンによる並べ替え、本文保持、部分JSONの往復、旧バックアップの読み込みを検証。APKはビルド・lint・署名を確認し、実機画面の確認は未実施。
